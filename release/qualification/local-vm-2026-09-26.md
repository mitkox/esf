## Checks performed

- Backed up the pre-upgrade factory files, Temporal PostgreSQL databases, and
  Cube MySQL and MinIO state. Restored the Temporal SQL dump into an isolated
  PostgreSQL 16.15 container; the temporal and visibility schema versions were
  1.19 and 1.14. Re-extracted the factory snapshot and confirmed 35 run
  directories and 29 change records. This does not replace a full service and
  QMS recovery drill.
- `make temporal-up temporal-hello` passed. The hello target now includes the
  integration build tag; previously it reported success while running zero
  tests. Legacy Temporal history replay, real-server workflow execution,
  cancellation, timeout cleanup, and the 190-second heartbeat test passed.
- All seven live Cube integration scenarios passed on 0.7.2: create/execute/
  destroy, file round trip, runtime network policy, Git workflow, idempotent
  destroy, template lookup, and metadata recovery.
- A factory conformance run produced a verified patch and left no sandbox.
  Both R2 and R3 assurance integration runs passed, including approval,
  cleanup, and encrypted history replay. A second conformance run on the
  versioned template also passed with no sandbox leak.
- `factory config validate`, the development-profile `factory doctor`, and
  `factory agents verify` passed. Frontend tests passed (40), the Vite build
  passed, and optional Python tests passed (15). The PR's Linux and macOS CI
  checks passed on the initial implementation commit.
- The local conformance script took 24.5 seconds with the old template and
  3.5 seconds with the versioned template. The deterministic 1/4/8-run fixture
  then passed all 13 runs on the pinned template and all 13 comparison runs on
  the old template, with one agent attempt per run, verified cleanup, and no
  remaining sandbox. [The benchmark record](../benchmarks.md) gives latency,
  worker RSS, evidence size, and the limits of this comparison.
- Real OpenCode V2 and Unreal 0.2.0 runners passed model-backed acceptance
  with the pinned Cube template and the local model service at
  a private LAN model endpoint. OpenCode run
  `run-ceabe93562d63e845b25c027` and Unreal run `run-8e3d5f856f64f4d520503487` each produced a verified patch,
  passed build and test gates, and verified sandbox cleanup. Previous failed
  attempts during a model-server outage also cleaned up their sandboxes.
- A separate owner-only OpenCode Go profile used DeepSeek V4.1 Flash with a
  `0600` key file, HTTPS endpoint, CubeEgress credential injection, and no
  raw runtime egress. The Go `/models` endpoint authenticated and listed the
  model; a direct host Chat Completions request succeeded. Two disposable
  factory attempts (`run-e2cb5e7778d33823996df12b` and
  `run-cbed194e3dcfd1d8ed623f75`) were cancelled after Cube's HTTPS L7
  route failed to connect. Both reported verified cleanup and no remaining
  sandbox. The second attempt had a pinned model catalog and intake disabled.
  The private test configuration is
  `$HOME/.local/share/esf/upgrades/factory-v05-opencode-go.toml`;
  its key is referenced by path only. The read-only catalog snapshot is
  `$HOME/.local/share/esf/upgrades/opencode-models-20260926.json`,
  SHA-256 `e66aa77c55c5cfef14f8d41df5216fb422a82407000d8e13593920b99f1b421d`.
  The expanded Cube integration probe reproduces the L7 timeout without the
  Go key, while public egress and DNS/domain allow rules work. This is a
  Cube host data-path blocker; it does not qualify the Go profile yet.
- The Cube 0.7.2 host proxy initially used the installer default sandbox
  network CIDR, which did not match the running `cube-dev` network. The host
  env file was backed up, its CIDR was corrected, and only
  `cube-sandbox-cube-egress-net.service` was restarted. The TPROXY target
  was corrected to the active CubeEgress endpoint. A fresh L7 probe still
  timed out: the `TRANSPROXY` return rule counted 26,830 packets after the probe while both
  HTTP and HTTPS mark-matching rules counted zero. CubeEgress logged no
  sandbox request. The next diagnosis is the CubeVS `allow_out_v3` and DNS
  maps while a disposable sandbox is live, to determine why its HTTPS packets
  are not stamped with the L7 mark. The probe always destroys its sandbox.
- The local optional intake was moved to a separate Python 3.14.7 environment
  resolved from `uv.lock`. A fresh conformance run with intake enabled passed
  and left no sandbox. The runtime check confirmed that DSPy's disk cache is
  disabled and its memory cache is capped at 1,024 entries. The separate
  [dependency scan](dependency-scan-2026-09-26.md) records the transitive
  DiskCache advisory and the remaining security work.

## Final-release gates still open

- The local development configuration deliberately uses plaintext loopback
  Temporal and legacy environment credentials; `factory doctor --profile
  production` correctly fails its Temporal TLS and agent credential-mode
  checks. Production-profile VM qualification still needs a TLS-enabled
  Temporal endpoint and controlled agent credentials.
- CubeEgress HTTPS L7 interception must pass the new live request probe and
  OpenCode Go must then pass a full patch, verification, and cleanup run.
- The MicroK8s server was upgraded to 1.36.2 on 2026-09-27; its node reports
  Ready. Helm 4.3.0 chart syntax was checked, but Kubernetes 1.36.2 deployment
  qualification, Cube node drain, and Kubernetes restore are not covered by
  this VM test.
- A published candidate-image digest, image provenance, a full VM/QMS restore
  and rollback, the Kubernetes 1/4/8-run performance matrix, the 24-hour soak, the
  failure/security matrix, and transitive-license review remain pending.
- Fresh Grype scans found no matches in the factory and console runtime
  images. The managed-worker, optional intake, and Cube template images have
  high/critical matches requiring patching or a documented exploitability
  review; see [the dependency scan](dependency-scan-2026-09-26.md).

`scripts/verify-release-inventory.py --require-qualified` must continue to
reject final promotion until those gates have evidence and are marked passed.
